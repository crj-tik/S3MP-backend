# S3 存储服务使用指南

> 面向 `dwh-chatbi` 开发者及协作 Codex。本文合并公司 S3 申请/API/使用指南、历史最佳实践评论和仓库当前实现。公司平台页面与本文冲突时，以公司平台最新页面为准；本文中的性能数字和联系人只视为资料快照。

## 1. 先看结论

- 公司存储服务只兼容 **AWS S3 协议的一个子集**，不能默认所有 AWS S3 能力都可用。
- 服务端应用优先使用内网端点 `http://storage.lianjia.com`；需要外网访问时才评估 `http://ods.lianjia.com`。当前不支持 bucket 泛域名访问，必须使用 path-style URL：`http://endpoint/bucket/object-key`。
- 使用 V4 签名。所有 SDK 客户端都必须配置公司 endpoint、region 和 path-style；不要照搬 AWS 公有云默认配置，也不要为了接入 S3 顺带升级项目运行时或 SDK 大版本。
- bucket 默认选 `private`。下载使用短时 GET 预签名 URL；前端直传使用短时 PUT 预签名 URL。只有经过业务和安全评估后才申请 `public-read`。
- AK/SK 是生产凭证，不得写进源码、配置默认值、文档、测试数据、日志或提交给 Codex 的提示词；应由部署环境的密钥配置注入。
- 当前仓库依赖 `aws-java-sdk-s3:1.11.336`，现有客户端也是 SDK 1.x。公司评论中提到的 SDK 2.20 示例不能直接复制到本仓库；升级 SDK 2.x 应单独设计和验证。
- 新业务先判断能否复用 `SkillS3Client` 或 `S3Client`，不要在业务 Service 中再创建一套 `AmazonS3`。

## 2. 公司 S3 与 AWS S3 的差异

### 2.1 端点和 URL 形式

| 场景 | endpoint | 说明 |
|---|---|---|
| 服务端内网访问 | `http://storage.lianjia.com` | 默认选择，`SkillS3Client` 当前使用 |
| 外网访问 | `http://ods.lianjia.com` | 仅在确有外网访问需求时使用，`S3Client` 当前使用 |

平台当前不支持 `bucket.endpoint` 形式。SDK 必须启用 path-style，最终路径形如：

```text
http://storage.lianjia.com/<bucket>/<object-key>
```

不要把上面的拼接地址当成私有对象的永久下载地址。`private` bucket 需要通过 SDK 鉴权读取，或由服务端生成限时预签名 URL。

### 2.2 已知支持能力

公司 API 文档列出的能力如下；开发前仍应确认目标操作在当前平台可用。

| 类型 | 操作 |
|---|---|
| Bucket | `CreateBucket`、`DeleteBucket`、`GetBucketAcl`、`HeadBucket`、`ListBuckets`、`PutBucketAcl` |
| Object | `CopyObject`、`DeleteObject`、`GetObject`、`HeadObject`、`ListObjects`、`PutObject` |
| Multipart | `CreateMultipartUpload`、`UploadPart`、`UploadPartCopy`、`ListParts`、`CompleteMultipartUpload`、`AbortMultipartUpload` |
| Presign | private bucket 的临时下载链接；公司资料记载默认 15 分钟，SDK 传入的到期时间以平台实际限制为准 |

平台还有控制面使用的 bucket 元数据能力，例如单请求最大上传大小和域名白名单，但 SDK 文档没有对应标准方法。不要自行假设 CORS、事件通知、版本控制、生命周期、存储类型、对象锁等 AWS 能力可用。

### 2.3 上传和下载元数据

上传可设置 `Content-Type`、`Content-Length`、`Content-MD5`、`Cache-Control`、`Content-Disposition`、`Content-Encoding`、`Content-Language`、`Expires`。下载时平台会返回已保存的相关头。

工程约束：

- 流式上传必须提供准确的 `Content-Length`，避免 SDK 缓冲整个流或签名不一致。
- 设置真实的 `Content-Type`，未知二进制文件使用 `application/octet-stream`。
- 生成 PUT 预签名 URL 时如果把 `Content-Type` 纳入签名，客户端上传请求必须发送完全相同的值。
- 对用户可控文件名进行清洗；object key 使用业务固定前缀、稳定 ID 和扩展名，不接受 `..`、前导 `/` 或任意路径片段。

### 2.4 签名

使用 V4 签名。公司历史指南指出，V2 预签名会把 HTTP Method、`Content-Type`、`Content-MD5` 等参数纳入签名，而且 Signature 可能需要 URL encode，排查成本更高。

历史评论还记录过 SDK 1.x 的 MD5 校验/分块编码兼容问题：

```java
.withPayloadSigningEnabled(false)
.disableChunkedEncoding()
```

这两个选项只应在复现 MD5 校验或 chunked encoding 兼容错误后增加，并完成上传、下载、预签名和大文件回归；不要为了“最佳实践”无条件修改全局客户端。相比设置 JVM 全局属性关闭下载 MD5 校验，优先使用客户端级配置，缩小影响范围。

## 3. Bucket 申请流程

申请入口（公司内网）：[S3 新增 Bucket 申请流程](https://wiki.lianjia.com/pages/viewpage.action?pageId=480002458)。

### 3.1 前置：创建并登记服务

1. 在[贝壳云服务云](https://cloud.ke.com/console/project/cloud/overview)创建或选择业务服务。
2. 在 [KePaaS IAM](https://paas.ke.com/subability/iam/supplier/list) 登记该服务。
3. 获取并妥善保存 AK、SK 和 IAM Principal。存储服务目前要求在服务云/KePaaS 的生产环境操作；必须先完成登记，否则 bucket 无法使用。

### 3.2 提交 bucket 申请

在私有云对象存储控制台提交申请：

- [对象存储入口一](http://cloud.intra.ke.com/storage/bucket)
- [对象存储入口二](http://cloud.intra.ke.com/console/project/s3bucket/dashboard)

填写前准备：

| 字段 | 填写规则 |
|---|---|
| 经营单元/产品树 | 选择真实归属节点 |
| Bucket 名称 | 使用小写字母、数字和 `-`；不能以 `-` 开头或结尾；不超过 40 字符。截图占位曾出现下划线说法，与正文不一致，按更严格的连字符规则执行 |
| service_id | 选择服务云已注册的服务 |
| Principal | 填上一步获得的 IAM 标识 |
| CDN | 默认“不使用”；需要多媒体图片处理、文件预览或长期公开访问出口时再评估启用，资料记载启用后存储成本约为不启用的两倍 |
| ACL | 默认 `private`；申请 `public-read` 时写明原因、使用场景、bucket 名称和存储内容 |
| 安全级别 | 按实际数据分级选择，不得为了简化审批降级 |
| 敏感信息 | 文件含姓名、身份证、手机号、住址等敏感字段时如实选择并遵循脱敏规范 |
| 备注/业务场景 | 写明数据来源、存储内容、读写方、保留时长、预计容量/文件大小/QPS、是否需要预签名或 CDN |

### 3.3 审批后验收

不要先在业务代码中试错。用最小测试对象完成以下验收：

1. 用 `HeadBucket` 验证网络、endpoint、签名、凭证、bucket 和基础权限。
2. 用限定 prefix 和返回数量的 `ListObjects` 验证列表权限，避免一开始扫描整个 bucket。
3. 选择已知、非敏感的小对象执行 `GetObject`，校验内容长度、类型和摘要。
4. 如业务需要写入，再用唯一测试 key 上传小文件，读回验证后清理；未经明确授权不操作生产数据。
5. private bucket 不能通过无签名永久 URL 直接读取；GET 预签名 URL 在有效期内可访问，过期后不可访问。
6. 如使用 PUT 预签名，校验正确 `Content-Type` 可上传，签名字段不匹配时会失败。
7. 确认业务运行环境的网络和 AK/SK 注入正常；不要用个人电脑保存长期凭证。

普通单段对象的 ETag 经常等于内容 MD5，但 multipart、加密或平台实现差异下不保证相等。完整性验收应同时检查字节数、`Content-Type` 和业务保存的摘要，不能无条件把 ETag 当作 MD5。

## 4. `dwh-chatbi` 当前实现

### 4.1 依赖版本

`pom.xml` 当前使用 AWS Java SDK 1.x：

```xml
<dependency>
    <groupId>com.amazonaws</groupId>
    <artifactId>aws-java-sdk-s3</artifactId>
    <version>1.11.336</version>
</dependency>
```

公司评论在 2023 年提到 SDK 2.20 的新示例，但提供的评论正文仍主要是 SDK 1.x API。Codex 修改本仓库时必须以 `pom.xml` 和现有 import 为准，不能混用 `software.amazon.awssdk.*` 与 `com.amazonaws.*`。

### 4.2 三条 S3 相关链路

| 链路 | 入口 | endpoint / bucket | 当前用途 |
|---|---|---|---|
| 通用报表文件 | `infra/common/client/s3/S3Client.java` | 外网 endpoint；`s3.bucket` | CSV/XLSX 上传、GET 预签名；`ChartUploadService` 使用 |
| Skill 文件与报告 | `infra/common/client/s3/SkillS3Client.java` | 内网 endpoint；dev/test 与 preview/prod 分桶 | `.skill` 包上传/读取/复制、HTML 报告、GET/PUT 预签名 |
| 灵珠代理上传 | `infra/common/client/lingzhu/LingzhuClient.java` | 调用灵珠 `/api/s3/uploadFile` | 个人/公共/角色知识文档；不直接使用本仓库 AK/SK 客户端 |

`SkillS3Client` 的环境选桶规则是：`preview`、`prod` 使用生产 bucket，其余 profile 使用测试 bucket。新增 profile 前必须确认此默认分支是否符合预期。

### 4.3 配置项

配置值应由配置中心或部署环境注入。以下只列键名，不提供真实凭证：

```properties
# 通用报表客户端
s3.endpointWAN=http://ods.lianjia.com
s3.AccessKeyId=${S3_ACCESS_KEY_ID}
s3.AccessKeySecret=${S3_ACCESS_KEY_SECRET}
s3.bucket=<bucket-name>

# Skill 客户端
s3.skill.endpoint=http://storage.lianjia.com
s3.skill.accessKeyId=${S3_SKILL_ACCESS_KEY_ID}
s3.skill.secretAccessKey=${S3_SKILL_SECRET_ACCESS_KEY}
s3.skill.testBucket=<test-bucket-name>
s3.skill.prodBucket=<prod-bucket-name>
s3.skill.presignExpireMillis=900000
```

注意两个客户端的过期时间单位不同：

- `S3Client.generatePreSignedURL(key, expireSecond)` 接收秒。
- `SkillS3Client.generateDownloadUrl(key, expireMillis)` 和 `generateUploadUrl(...)` 接收毫秒。

调用处应使用 `Duration` 转换并写清单位，避免把 15 分钟误配成 15 秒或数天。

### 4.4 优先复用的调用方式

上传内存内容并生成短时下载链接：

```java
byte[] bytes = content.getBytes(StandardCharsets.UTF_8);
String objectKey = "skill/report/" + safeFileName;

skillS3Client.uploadStream(
        objectKey,
        new ByteArrayInputStream(bytes),
        bytes.length,
        "text/html; charset=UTF-8"
);

String downloadUrl = skillS3Client.generateDownloadUrl(
        objectKey,
        Duration.ofMinutes(15).toMillis()
);
```

读取对象时由调用方关闭流：

```java
try (InputStream inputStream = skillS3Client.openStream(objectKey)) {
    // 在大小限制内处理内容
}
```

前端直传时由服务端生成 PUT 预签名 URL，不把 AK/SK 下发到浏览器：

```java
String uploadUrl = skillS3Client.generateUploadUrl(
        objectKey,
        Duration.ofMinutes(10).toMillis(),
        contentType
);
```

前端 PUT 请求必须使用生成 URL 时相同的 `Content-Type`。上传完成后，服务端还应校验 object key、对象存在性、大小和类型，再把 key 记录到业务表。

## 5. 设计与安全规范

### 5.1 权限和凭证

- 一个服务使用自己的 IAM Principal 和凭证，不复用其他业务的 AK/SK。
- 权限按 bucket 和操作最小化；业务运行时通常不应拥有创建/删除 bucket、修改 ACL 的权限。
- 优先 private bucket + 预签名 URL。`public-read-write` 不进入正常业务选项。
- AK/SK 只存在于密钥配置系统和进程运行环境；日志中仅记录配置来源、endpoint、bucket，不记录凭证。
- 不向 Codex、工单、聊天或文档粘贴真实 AK/SK。需要排错时只提供脱敏后的前后少量字符和错误码。
- 怀疑泄露时立即吊销/轮换并检查访问日志，不能只删除 Git 中的字符串。

### 5.2 object key 和数据生命周期

推荐结构：

```text
<business>/<tenant-or-user>/<yyyy>/<MM>/<stable-id>.<ext>
```

- key 表示逻辑位置，不等同于本地文件路径；数据库保存 object key，不保存带签名参数的临时 URL。
- 用 UUID/业务 ID 保证唯一性。覆盖是显式业务语义，不能因文件同名而静默覆盖。
- 明确保留期和清理方式。公司兼容服务未声明支持 AWS 生命周期策略时，由业务任务执行可审计清理。
- 上传前限制单文件大小、总量、扩展名和 MIME；压缩包下载/解压还要限制条目数、解压后总大小和路径穿越。

### 5.3 预签名 URL

- 有效期按业务最短化，普通上传/下载优先 10-15 分钟；确需更长时间时记录原因并验证平台上限。
- 预签名 URL 等同于有效期内的临时凭证，不写入日志、埋点、异常消息或数据库长期字段。
- URL 过期是正常状态，客户端需要重新向业务服务申请，不应缓存为永久资源地址。
- 需要长期公开分发、图片处理或文件预览时评估 CDN/多媒体服务，不用超长预签名 URL 代替。

### 5.4 性能与大文件

公司使用指南给出的内网快照数据（未标注压测日期，应在容量评审时重新确认）：

| 文件大小 | 当时 QPS | 集群极限并发数 | 平均响应时间 |
|---|---:|---:|---:|
| 1 MB | 650 | 3200 | 80-150 ms |
| 1-10 MB | 150 | 3000 | 120-200 ms |
| 10-100 MB | 5 | 2400 | 700-1000 ms |
| 100 MB 以上 | 1 | 1800 | 3600-4000 ms |

- 大文件使用 multipart，失败时调用 `AbortMultipartUpload`，避免遗留未完成分片。
- 不要为获得 `Content-Length` 把不受限文件整体读入堆内存；可用临时文件、受限流或 multipart。
- 设置连接、读取、请求超时和有限重试；只重试幂等/可确认安全的操作，避免重复业务写入。
- 上线前按真实文件分布验证吞吐、P95/P99、内存、线程池和失败重试，不把上表当容量承诺。

### 5.5 日志和可观测性

成功日志建议记录：operation、bucket、脱敏/可公开的 object key、size、contentType、costMs、requestId。失败日志保留 SDK 状态码、错误码和 requestId。

不得记录：AK/SK、Authorization、Cookie、完整预签名 URL、文件正文、含个人信息的原始文件名。

## 6. 当前代码已识别风险

以下是编写本文时从 master 版本代码确认的现状，不代表建议做法：

1. `S3Client` 与 `SkillS3Client` 的 `@Value` 表达式含凭证默认值。应尽快轮换相关凭证、删除源码默认值，并改为启动时缺失即失败的外部配置。
2. `S3Client.generatePreSignedURL` 会记录完整预签名 URL；这会把临时访问凭证写入日志，应改为只记录 bucket/key/到期时间或 URL 指纹。
3. `ChartUploadService` 请求 7 天链接，而 `S3Client` 中声明的 `MAX_EXPIRE_SECONDS` 没有实际执行；需确认平台允许上限与业务必要性，并统一校验。
4. `S3Client.uploadOutputStreamToS3` 无论 CSV/XLSX 都设置 XLSX Content-Type，且上传前执行“存在则删除”；新增用途前应修正类型并确认覆盖语义。
5. 两个客户端重复维护初始化、签名和异常处理，配置键命名/过期单位也不一致。后续重构可统一配置模型和客户端工厂，但不应在普通业务需求中顺带迁移 SDK。

这些问题涉及凭证和线上兼容，修复时应单独提交、先确认部署配置已补齐，并完成上传/下载/预签名回归。

## 7. 排错清单

| 现象 | 优先检查 |
|---|---|
| `403` / `AccessDenied` | AK/SK 是否属于已登记服务；Principal 是否已授权目标 bucket；是否误用测试/非生产凭证；系统时钟是否正确 |
| `SignatureDoesNotMatch` | endpoint、region、V4 签名、path-style；HTTP Method；预签名时与请求实际发送的 Content-Type/MD5 是否一致；URL 是否被二次编码 |
| `NoSuchBucket` | profile 选桶规则；bucket 名称；申请是否审批完成；endpoint 是否正确 |
| `NoSuchKey` | 数据库保存的是 object key 还是完整 URL；前导 `/`；大小写；业务前缀；版本/环境是否串桶 |
| `PermanentRedirect` / host 错误 | 是否遗漏 path-style，误用了 `bucket.endpoint` 泛域名形式 |
| MD5 校验失败 | 先核对内容是否被代理修改、长度/摘要是否正确；确认是兼容问题后，再验证 payload signing/chunked encoding 客户端选项 |
| 预签名 URL 立即失效 | 秒/毫秒是否混淆；机器时钟；URL 是否被 HTML/网关转义；请求头是否与签名一致 |
| 上传慢或内存高 | 是否把大文件整体转为 `byte[]`；是否应 multipart；文件大小、并发、超时和重试配置 |
| 浏览器 PUT 失败 | CORS/平台支持情况；Content-Type 是否完全一致；URL 是否过期；浏览器是否额外添加了参与签名的头 |

## 8. 给 Codex 的执行约束

让 Codex 开发 S3 需求时，可直接引用本文，并补充明确的业务信息：现有或指定技术栈、运行环境、客户端链路、对象大小、读写方、保留期、ACL、预签名有效期和允许修改的文件范围。已有工程优先复用现有客户端和 SDK；空目录项目先检查当前环境，再选择维护状态正常的官方 SDK，不强制使用某一种语言。

Codex 必须遵守：

1. 先读本文件、仓库 `AGENTS.md`、实际依赖清单（如 `pom.xml`、`pyproject.toml` 或 `package.json`）和目标调用链，再修改代码。
2. 搜索结果出现凭证时不得在回复、补丁、测试或文档中复述；发现源码凭证只报告位置和风险。
3. 默认复用现有客户端；若现有能力不足，先列出缺口和兼容影响。
4. 不创建/删除 bucket、不改 ACL、不轮换凭证、不调用真实生产上传，除非用户明确授权且目标已核对。
5. 测试使用 mock/fake 和占位凭证；集成测试必须使用专用测试 bucket、唯一前缀，并清理测试对象。
6. 不把 SDK 2.x 示例混入当前 SDK 1.x 工程；升级依赖必须作为独立任务。
7. 交付时说明：改动文件、配置项、权限前提、测试证据、回滚方式和仍需人工完成的申请/密钥操作。

推荐提示词：
