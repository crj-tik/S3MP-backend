### 三、关键发现

#### 发现 1：后端实现覆盖率 ~31%

后端只实现了 20/64 个端点，集中在 identity 和 authorization 两个模块。以下模块有领域/基础设施代码但**缺少 API 路由层**：

| 模块 | 域代码 | 基础设施 | API 路由 |
|---|---|---|---|
| applications | ✅ | ✅ | ❌ |
| files | ✅ | ✅ | ❌ |
| storage | ✅ | ✅ | ❌ |
| audit | ✅ | ✅ | ❌ |
| governance | ✅ | ✅ | ❌ |
| tenant | ✅ | ✅ | ❌ |

这些模块的 `api/` 目录下只有 `__init__.py`，没有实际路由文件。

#### 发现 2：前端 MSW Mock 路径错误

`src/api/mock/handlers.ts:52`：
```typescript
http.get(`${apiBase}/api_keys`, ...)
```

契约定义 `list_api_keys` 的路径是 `/applications/{application_id}/api_keys`（需要 `application_id` 路径参数），不是 `/api_keys`。这个 Mock 在真实联调时会 404。

#### 发现 3：错误码名称不一致

| 场景 | 契约错误码 | 前端 Mock 错误码 |
|---|---|---|
| 会话过期 | `authentication_required` | `session_expired` |
| 权限拒绝 | `permission_denied` | `permission_denied` ✅ |
| 资源过期 | `resource_expired` | `resource_expired` ✅ |
| 配额超限 | `quota_exceeded` | `quota_exceeded` ✅ |

`handlers.ts:28-32` 中过期场景返回 `session_expired`，但 `error-codes.yaml` 中的标准错误码是 `authentication_required`。`session_expired` 不在标准错误码列表中。

#### 发现 4：前端类型与契约 Schema 一致 ✅

前端 `src/api/generated/openapi.ts`（3150 行）由 `openapi-typescript` 从后端 `contracts/openapi.yaml`（841 行）生成，逐字段对比 100% 一致。生成管线已验证：

```
contracts/openapi.yaml  →  openapi-typescript  →  src/api/generated/openapi.ts
       (841 行)                                      (3150 行, 含注释)
```

所有 Schema、参数、响应码、nullable 字段均正确映射。

#### 发现 5：后端错误处理基础设施与契约对齐 ✅

`src/s3mp/common/errors.py` 的 `ApiError` 类输出格式与契约 `Error` schema 一致：
- `code`（string）✅
- `message`（string）✅
- `request_id`（string）✅
- `details`（optional object）✅

`error-codes.yaml` 中定义的 23 个标准错误码在后端均可通过 `ApiError(code, message, status_code)` 抛出。
