# S3MP 配额分配模型

## 容量层级

共享 Bucket 的容量由 `S3MP_S3_BUCKET_CAPACITY_GIB` 配置，单位为 GiB。平台管理员先为租户配置总配额，再可以从租户总配额中静态划分应用独立配额；数据库内部仍以 bytes 精确记录。

```text
Bucket 容量
└── 租户总配额
    ├── 应用独立配额 A
    ├── 应用独立配额 B
    └── 共享剩余池（没有独立配额的应用共同使用）
```

应用独立配额未使用的空间不会自动回流共享池；撤销应用独立配额后才会重新进入共享池。

## 约束

- 租户总配额不得超过共享 Bucket 容量。
- active 应用独立配额之和不得超过租户总配额。
- 降低租户或应用配额时，不得低于已用量、进行中预留量或子配额总量。
- 没有租户总配额的租户不能创建新的文件上传会话。
- 只有平台级用户可以创建、调整和撤销应用独立配额；租户用户只读。

## API

平台控制面：

- `GET /api/v1/platform/quotas`
- `POST /api/v1/platform/quotas`
- `PATCH /api/v1/platform/quotas/{quota_id}`
- `DELETE /api/v1/platform/quotas/{quota_id}`：仅撤销没有使用量和预留量的应用独立配额

租户侧的 `GET /api/v1/quotas` 只返回当前租户的有效配额。

### 前端与部署迁移

- 配置共享 Bucket 容量时使用 `S3MP_S3_BUCKET_CAPACITY_GIB=<整数>`；旧的 `S3MP_S3_BUCKET_CAPACITY_BYTES` 不再生效。
- 创建或调整配额时，`POST /api/v1/platform/quotas`、`PATCH /api/v1/platform/quotas/{quota_id}` 和 `PATCH /api/v1/quotas/{quota_id}` 使用整数 `limit_gib`，例如 `{"limit_gib": 50}`。
- `limit_bytes` 不再是请求字段。容量展示优先使用响应中的 `*_gib` 字段；保留的 `*_bytes` 字段仅用于精确诊断，不应由前端编辑后回写。

## 回滚与历史数据

旧 storage-space 配额会被标记为 `legacy`，不会成为新的平台分配入口。迁移期间仍允许其受控完成已有上传，平台应通过 `scripts/audit_quota_allocations.py` 检查有使用量或预留量的历史记录，再决定转换到租户/应用模型。
