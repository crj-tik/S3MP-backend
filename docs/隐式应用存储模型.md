# 隐式应用存储模型

平台使用统一共享 S3 Bucket。租户和应用不创建、不绑定、不解绑也不选择独立存储空间。

- 创建租户时，服务端以不可变租户 slug 派生默认逻辑根路径，例如 `sft-test`。
- 创建应用时，服务端在同一数据库事务中创建应用唯一内部存储记录。
- 应用路径固定为 `<tenant_slug>/<application_id>`，例如 `sft-test/6f...`。
- 应用重命名不会改变路径，也不会搬迁已有对象。
- 应用接口只读展示路径、状态、用量和配额；Bucket、连接、凭据及物理 URL 不公开。
- 文件、目录授权和配额以应用为业务入口。`storage_space_id` 只作为迁移期内部兼容键。

旧 `/storage_spaces/{space_id}/...` 文件路由仅为兼容已有客户端暂留并标记 deprecated；新客户端必须使用 `/applications/{application_id}/...`。公开的 `POST /storage_spaces` 已删除。

历史数据升级前必须执行 namespace 审计。缺失且归属唯一的内部记录可以补建；重复 namespace、跨租户归属、多个活动记录或未完成任务 namespace 漂移必须先隔离或修复，不得静默选择或重写 provider key。
