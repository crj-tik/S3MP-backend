# S3MP 应用文件上传与下载接口

本文面向已在 S3MP 中注册的第三方应用及其管理后台，说明如何在应用自己的文件命名空间内上传、查询和下载文件。

## 1. 接口与身份模型

浏览器文件浏览页面与第三方应用服务端共用同一组应用级文件接口；区别只在认证方式和授权来源。

| 调用方 | 凭据 | 写请求附加要求 | 授权来源 |
| --- | --- | --- | --- |
| 管理后台浏览器 | 租户会话 Cookie | `X-S3MP-CSRF` | 当前登录成员的租户角色与目录授权 |
| 第三方应用服务端 | `Authorization: S3MP-Key <key_id>.<secret>` | 无 CSRF | API Key scope 与该应用授权代表的租户角色/目录授权的交集 |

两类调用都使用相同的应用级路由，例如：

```text
POST /api/v1/applications/{application_id}/direct_uploads
GET  /api/v1/applications/{application_id}/files
POST /api/v1/applications/{application_id}/presigned_downloads
```

`application_id` 是显式资源标识：对浏览器会话，它指定用户正在管理的应用；对 API Key，后端还会校验它必须与该 Key 所属应用一致。API Key 不能借此访问其他应用的文件命名空间。

## 2. 前置条件

- API 根地址：`{S3MP_BASE_URL}/api/v1`，本地开发环境通常为 `http://localhost:19101/api/v1`。
- 应用已启用，并已绑定有效的授权代表。
- API Key 同时具备所需 scope：
  - 查询文件：`files.list`
  - 上传及完成提交：`files.write`
  - 创建下载链接：`presigned_urls.issue`

鉴权头格式如下。不要把完整 Key、Cookie 或预签名 URL 写入日志、代码库或错误上报。

```http
Authorization: S3MP-Key <key_id>.<secret>
```

应用请求只能访问自己的命名空间。不要拼接 Bucket 名称、物理对象路径或 S3 provider upload ID。

## 3. 直传上传流程

小文件按三个步骤完成：创建上传会话、向短期 PUT URL 上传二进制内容、完成校验并提交。

### 2.1 创建直传会话

`POST /applications/{application_id}/direct_uploads`

请求头：

```http
Authorization: S3MP-Key <key_id>.<secret>
Content-Type: application/json
Idempotency-Key: <uuid-or-other-opaque-key>
```

请求体：

```json
{
  "object_key": "uploads/example/readme.md",
  "content_length": 174,
  "content_type": "text/markdown; charset=utf-8",
  "expires_at": "2026-08-20T10:00:00Z"
}
```

`object_key` 是应用命名空间内的相对路径；`content_length` 必须是实际字节数；`expires_at` 必须是未来的 UTC RFC 3339 时间。`checksum` 为可选字段；如果使用，必须同时在后续 PUT 中逐字携带响应要求的校验头。

成功响应为 `201`，核心字段如下：

```json
{
  "id": "<upload_id>",
  "status": "pending",
  "object_key": "uploads/example/readme.md",
  "method": "PUT",
  "url": "<short-lived-presigned-url>",
  "headers": {
    "Content-Type": "text/markdown; charset=utf-8"
  },
  "expires_at": "2026-08-20T10:00:00Z"
}
```

`url` 和 `headers` 只在当前会话内使用；应只在内存中保存，并在过期前完成上传。

### 2.2 PUT 文件内容

对上一步返回的 `url` 执行 `PUT`，并逐字使用响应中的 `headers`。该请求发往对象存储，不再使用应用 API Key。

```bash
curl --request PUT "$UPLOAD_URL" \
  --header 'Content-Type: text/markdown; charset=utf-8' \
  --data-binary '@./readme.md'
```

如果响应 `headers` 中有额外字段（例如 `x-amz-checksum-sha256`），也必须携带相同值。不要自行修改预签名 URL 的查询参数。

### 2.3 完成并提交

`POST /direct_uploads/{upload_id}/completion`

```bash
curl --request POST "$S3MP_BASE_URL/api/v1/direct_uploads/$UPLOAD_ID/completion" \
  --header "Authorization: S3MP-Key $S3MP_API_KEY" \
  --header 'Content-Type: application/json' \
  --header "Idempotency-Key: $(uuidgen)" \
  --data '{}'
```

成功响应为 `200`，其中 `status: "committed"` 表示文件已成为可查询对象：

```json
{
  "id": "<ingestion_id>",
  "status": "committed",
  "file_object": {
    "id": "<file_id>",
    "object_key": "uploads/example/readme.md",
    "content_length": 174,
    "content_type": "text/markdown; charset=utf-8",
    "status": "available"
  }
}
```

## 4. 查询文件

`GET /applications/{application_id}/files`

可选查询参数：`prefix`（相对路径前缀）和 `status`（默认 `available`）。

```bash
curl --get "$S3MP_BASE_URL/api/v1/applications/$APPLICATION_ID/files" \
  --header "Authorization: S3MP-Key $S3MP_API_KEY" \
  --data-urlencode 'prefix=uploads/deep-interview/'
```

响应是文件数组，使用 `id` 作为下载接口的 `file_id`：

```json
[
  {
    "id": "<file_id>",
    "object_key": "uploads/example/readme.md",
    "content_length": 174,
    "content_type": "text/markdown; charset=utf-8",
    "status": "available",
    "etag": "<opaque-etag>",
    "created_at": "2026-08-20T09:32:33Z"
  }
]
```

## 5. 下载文件

先创建短期下载链接，再对该链接执行 `GET`。

`POST /applications/{application_id}/presigned_downloads`

```bash
DOWNLOAD_TICKET=$(curl --silent --request POST \
  "$S3MP_BASE_URL/api/v1/applications/$APPLICATION_ID/presigned_downloads" \
  --header "Authorization: S3MP-Key $S3MP_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"file_id":"<file_id>","ttl_seconds":300}')
```

响应示例：

```json
{
  "method": "GET",
  "url": "<short-lived-presigned-url>",
  "file_id": "<file_id>",
  "expires_in": 300
}
```

从响应中取出 `url` 后下载：

```bash
curl --location "$DOWNLOAD_URL" --output ./downloaded.md
```

## 7. 常见错误

| HTTP 状态 | `code` | 常见原因与处理 |
| --- | --- | --- |
| 401 | `authentication_required` | Key 缺失、格式不正确或无效。确认鉴权头是 `S3MP-Key <key_id>.<secret>`。 |
| 403 | `permission_denied` | Key 缺少 scope，或应用授权代表、角色绑定、租户状态已失效。上传需 `files.write`，列表需 `files.list`，下载签名需 `presigned_urls.issue`。 |
| 404 | `resource_not_found` | 应用 ID、上传 ID 或文件 ID 不存在，或不属于当前应用命名空间。 |
| 409 | `idempotency_key_reused` | 同一 `Idempotency-Key` 被用于不同请求内容。为新的业务动作生成新 Key。 |
| 409 | `upload_verification_failed` | PUT 内容长度、Content-Type 或校验头和创建会话声明不一致。重新创建会话后，按返回的 URL 与 headers 上传。 |
| 410 | `resource_expired` | 上传会话或预签名 URL 已过期。重新创建会话或下载链接。 |

错误响应中的 `request_id` 可用于向 S3MP 运营方排障；客户端应基于稳定的 `code` 分支处理，而不是解析 `message`。

## 8. 实现建议

- 创建和完成上传各使用独立的 `Idempotency-Key`；网络重试时复用同一个语义请求的 Key。
- 将上传文件以二进制读取，按实际字节数填充 `content_length`。
- 不记录完整 API Key、预签名 URL、文件正文或敏感原始文件名。
- 大文件应使用 `/applications/{application_id}/multipart_uploads` 分片上传，避免整文件缓存在客户端内存中；其会话创建、分片上传和 completion 的原则与直传一致。
