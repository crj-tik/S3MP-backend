# 生产环境 S3 适配分析报告

> 分析依据：`docs/S3存储服务使用指南.md` 与当前 S3MP 后端实现。
>
> 本报告仅用于记录分析结论，当前不执行代码、配置或部署调整。

## 结论

当前 S3MP 的核心协议层能够对接该生产 S3：已使用 boto3，支持 SigV4、path-style，并实现 Head、Put、Delete、Copy、Multipart 和 GET 预签名能力。但不能直接替换生产参数后上线。

主要差距来自该生产存储是有限的 S3 兼容实现：强制内网 HTTP 与 path-style，bucket 需要审批，能力并非完整 AWS S3；而 S3MP 当前的生产安全策略、直传能力、存储连接运行时模型与其存在冲突。

## 可以直接复用的能力

| 生产要求 | 当前 S3MP 状态 | 结论 |
|---|---|---|
| endpoint、region、path-style | boto3 已配置 `endpoint_url`、`region_name`、`addressing_style` | 可用 |
| SigV4 | boto3 默认使用 SigV4，代码另有 SigV4 实现 | 基本可用，建议显式固定 |
| private bucket | 服务端鉴权并提供 GET 预签名下载 | 可用 |
| HeadObject 校验 | 已实现并用于上传提交验证 | 可用 |
| Put、Delete、Copy | 已实现 | 可用 |
| Multipart 创建、分片、完成、取消 | 已实现对应 boto3 调用 | 基础可用 |
| 内网优先 | endpoint 可配置 | 可用，需使用公司内网 endpoint |
| 预签名有效期 10–15 分钟 | 下载默认 900 秒，最大 3600 秒 | 与文档基线兼容 |

## 上线前必须调整

### P0：生产内网 HTTP 策略

生产文档使用 `http://storage.lianjia.com`，而当前配置校验禁止 production 使用 HTTP。需要增加受信任内网 endpoint 白名单或显式开关，不能直接放开所有 HTTP。

### P0：显式固定 path-style 与 SigV4

当前 `S3MP_S3_PATH_STYLE` 默认值为 `true`，但生产部署必须显式配置。boto3 客户端也应显式指定 `signature_version="s3v4"`，避免依赖 SDK 默认行为。

### P0：生产凭据注入方式

当前 production 配置强制使用 `S3MP_S3_ACCESS_KEY_FILE` 与 `S3MP_S3_SECRET_KEY_FILE`。生产文档要求由部署环境或密钥配置系统注入。如果公司平台只支持环境变量注入，当前启动校验会阻止服务启动，需要统一 Secret 注入标准。

### P0：Bucket 审批与白名单

生产 bucket 需要绑定 `service_id`、IAM Principal、ACL 和安全等级。当前创建 storage space 时可以填写任意 bucket 名称，未强制绑定审批信息。应改为只允许已批准的 bucket，或接入 bucket 注册信息。

### P0：前端 PUT 预签名直传

生产文档要求 private bucket 的浏览器直传使用短期 PUT 预签名 URL。当前只有 GET 预签名；`direct_requested` 尚未形成真正的 PUT 预签名流程。需要补充 PUT 预签名、完成回调校验及契约。

### P0：Bucket CORS

浏览器直传依赖 bucket CORS。需要在 bucket 申请中登记前端 origin、`PUT` 方法和允许的请求头（至少 `Content-Type`，启用完整性校验时还包括 `Content-MD5`），并完成浏览器预检验收。

## 需要重点适配的功能

### 1. 上传完整性与元数据

当前实现部分依赖 `ChecksumSHA256`。生产文档强调 `Content-MD5`，同时明确不能把 ETag 无条件视为 MD5，因为 multipart、加密和平台实现差异都会破坏这一假设。

建议：

- 代理上传由服务端流式计算 SHA-256/MD5，并记录结果。
- PUT 预签名直传时，将约定的 `Content-Type` 和可选 `Content-MD5` 纳入签名。
- 完成时校验对象长度、类型和平台可返回的校验信息。
- 不把 ETag 当作 MD5。
- 如果生产平台不返回 SHA-256 字段，则不要强制要求 `ChecksumSHA256` 必须存在。

### 2. 大文件与内存安全

当前普通上传接口接收 `bytes`，会把整个请求体读入服务进程。生产文档明确不应为获得 Content-Length 而将不受限文件读入内存。

建议：

- 小文件保留代理上传，但增加单文件上限。
- 大文件强制使用 PUT 预签名或 multipart。
- 定义 multipart 阈值、最小分片大小、总文件上限、并发数和过期清理策略。
- 失败时执行 `AbortMultipartUpload`，并保留清理与重试记录。

### 3. 超时、重试与可观测性

当前 boto3 客户端没有显式设置连接超时、读超时和重试策略。应针对公司内网服务设置受控的 `connect_timeout`、`read_timeout` 和有限重试，并只重试幂等操作。

日志和指标至少应覆盖：

- operation、bucket、脱敏 object key、size、Content-Type、耗时和 S3 request id；
- SDK 状态码、错误码；
- 禁止记录 AK/SK、Authorization、Cookie、完整预签名 URL 和文件内容。

### 4. Bucket 与环境治理

生产文档要求 preview/prod 与测试 bucket 分离。S3MP 当前只有一个全局 `S3MP_S3_BUCKET`，数据库中的 storage connection / storage space 虽能记录多个 bucket，但运行时不会按 connection 动态创建不同的 S3 client。

需要二选一：

- 单连接部署模型：生产只允许一个经审批的 endpoint、IAM Principal 和 bucket，限制租户自行创建 storage connection；
- 多连接平台模型：实现 connection 到密钥引用、S3 client 工厂/缓存的运行时解析，按 storage space 选择客户端，并防止跨租户或跨 bucket 使用凭据。

当前实现更适合先采用单连接部署模型。

## 生产配置目标

不包含真实凭据：

```ini
S3MP_ENVIRONMENT=production
S3MP_S3_ENDPOINT=http://storage.lianjia.com
S3MP_S3_REGION=<公司规定的 region>
S3MP_S3_PATH_STYLE=true
S3MP_S3_BUCKET=<已审批的生产 bucket>

# 通过公司认可的 Secret 注入方式提供：
S3MP_S3_ACCESS_KEY_FILE=<secret-mount-path>
S3MP_S3_SECRET_KEY_FILE=<secret-mount-path>
```

HTTP 例外只能适用于明确的内网可信 endpoint，不能删除 production 的整体安全限制。

## 建议的上线验收顺序

1. 确认 `service_id`、IAM Principal、生产 bucket、权限范围和安全等级已审批。
2. 增加受控内网 HTTP 例外、SigV4/path-style 显式配置和生产 bucket 白名单。
3. 使用最小非敏感对象依次验证 HeadBucket、限定 prefix List、Head/Get、Put/Delete 和 GET 预签名。
4. 补充 PUT 预签名和 CORS 后，用真实浏览器验证预检、Content-Type 和过期失败行为。
5. 执行 multipart、超时、重试、权限拒绝、凭据轮换和日志脱敏验收。
6. 按真实文件分布进行吞吐、P95/P99、内存和并发压测。

## 建议新开 change 的范围

建议后续单独规划以下改动：

- 生产内网 HTTP endpoint 的受控放行；
- 生产 bucket 审批白名单；
- PUT 预签名、浏览器直传与 CORS；
- Content-MD5/SHA-256 等完整性策略适配；
- 大文件与 multipart 内存安全；
- boto3 超时、重试和观测指标；
- 单连接生产模式或多连接运行时客户端工厂。
