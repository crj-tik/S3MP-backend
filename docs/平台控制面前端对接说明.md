# 平台控制面前端对接说明

## 账户与权限边界

平台控制面使用账户会话 `s3mp_account_session`，变更请求使用账户 CSRF
Cookie 对应的 `X-S3MP-CSRF` 请求头。平台账户权限不会自动转换为租户权限；
进入租户必须先拥有正常 Membership 或已批准且未过期的 Support Access，
然后调用原有的租户选择接口。

## 查询接口

| 功能 | 接口 | 所需平台权限 | 分页 |
| --- | --- | --- | --- |
| 账户目录 | `GET /api/v1/platform/accounts` | `platform.accounts.read` | `items` + `next_cursor` |
| 账户详情 | `GET /api/v1/platform/accounts/{user_id}` | `platform.accounts.read` | 否 |
| 平台角色 | `GET /api/v1/platform/roles` | `platform.roles.read` | 当前返回完整角色目录 |
| 平台角色绑定 | `GET /api/v1/platform/role-bindings` | `platform.roles.read` | `items` + `next_cursor` |
| Support Access 队列 | `GET /api/v1/platform/support-access` | `platform.support.read` | `items` + `next_cursor` |
| Support Access 详情 | `GET /api/v1/platform/support-access/{request_id}` | `platform.support.read` | 否 |
| 平台审计 | `GET /api/v1/platform/audit-events` | `platform.audit.read` | `items` + `next_cursor` |
| 平台审计详情 | `GET /api/v1/platform/audit-events/{event_id}` | `platform.audit.read` | 否 |

分页请求使用 `limit` 和 `cursor`。`next_cursor` 是绑定当前用户、权限版本和
查询条件的签名游标，不能跨接口或跨筛选条件复用。

账户目录支持 `query`（邮箱、系统号或姓名）和 `status` 筛选。响应只包含账户
摘要，不包含密码、会话、API Key、存储凭据或租户权限。

## Support Access 页面状态

Support Access 状态由后端依据持久化状态计算：`pending`、`approved`、`revoked`、
`expired`。撤销优先于过期显示。批准仍需不同平台账户完成，不能由申请人自批。

批准成功后，前端应刷新账户上下文并显示目标租户及到期时间；用户必须显式选择
该租户后才建立租户会话。页面应持续显示“只读支持访问”和到期时间，不应把它
渲染成租户管理员。

Support Access 默认角色不含文件读写、删除、上传、下载、对象存储凭据或 API
Key 明文权限。撤销或过期后，前端应清理租户上下文并重新请求账户可选租户。

## 契约来源

前端类型生成以 `contracts/openapi.yaml` 为准。平台租户、角色绑定、Support
Access、审计和存储探测均使用明确响应 schema，不应再为这些响应添加
`unknown` 或 `as` 类型兜底。
