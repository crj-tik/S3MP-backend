## Context

当前数据库以一对一约束把 application 与 storage_space 关联，但两者通过独立 API 和独立前端流程创建。文件路由、RoleBinding 和部分配额查询仍以 storage_space_id 为公开寻址参数；应用本身已经持久化 `<tenant_slug>/<application_id>` namespace。实现必须保持共享 Bucket、安全隔离、已存在对象 Key 和异步任务可验证性。

## Goals / Non-Goals

**Goals:**

- 让租户根和应用子路径成为不可绕过的系统不变量。
- 应用创建完成时文件存储立即可用，不存在半初始化状态。
- 从业务 UI 和新公开 API 中移除 storage space 的创建、绑定和选择语义。
- 保持历史对象 Key、审计、授权、配额和异步任务可迁移、可回滚、可核验。
- 严格先完成后端与契约，再迁移前端。

**Non-Goals:**

- 不改变平台共享 S3 endpoint、Bucket 或凭据管理模型。
- 不因应用重命名或本 change 自动搬迁合法既有对象。
- 不立即删除所有包含 `storage_space_id` 的数据库列；它们可作为内部兼容键逐步收敛。

## Decisions

### 1. 保留内部一对一存储记录，但取消其业务资源身份

应用创建仓储在同一数据库事务中创建 application principal、application、owner/binding 和内部 storage_space。内部记录继续承载文件外键、授权和任务兼容信息，但不再拥有独立创建入口。

替代方案是立即删除 storage_space 表并把所有外键改成 application_id；该方案迁移面过大，容易破坏进行中的上传、任务和审计，因此分阶段处理。

### 2. 租户默认根是派生不变量

租户 slug 在创建后不可变，并作为默认根路径段；应用子路径始终使用 application UUID，不使用可变名称。数据库继续保存最终 namespace 作为审计和一致性校验值，运行时同时验证 tenant_id、application_id 和 namespace。

### 3. 应用创建是唯一初始化入口

应用和内部存储在同一事务提交。active 共享 profile 缺失、managed connection 建立失败、唯一约束冲突或授权基线失败均导致应用创建整体失败。应用响应嵌入 `storage` 只读摘要，避免前端二次查询和竞态。

### 4. 新公开接口按 application_id 寻址

新增或迁移文件、multipart、对象操作、授权和配额接口到应用上下文；服务层解析唯一内部空间后复用现有文件安全管线。旧 `/storage_spaces/{id}/...` 路由在过渡期仅为兼容客户端保留并标记 deprecated，`POST /storage_spaces` 直接移除。

### 5. 前端只展示存储，不管理存储

后端契约及测试通过后重新生成前端类型。应用详情显示路径、状态、用量和配额；移除全局创建入口、应用创建弹窗、空空间状态和所有空间候选选择器。文件操作在应用详情或应用选择上下文中进行；授权表单选择应用和目录。

### 6. 以审计迁移而非静默修复处理历史数据

迁移先扫描再写入：每个应用必须对应零或一个可证明同租户的内部空间。零个则安全补建；一个则校验并规范化展示信息；多个、跨租户、namespace 冲突或对象来源不明则隔离并生成报告。迁移不改写已验证合法的 provider key。

## Risks / Trade-offs

- [应用事务跨越现有仓储边界] → 合并到同一 SQLAlchemy session/transaction，并用故障注入测试证明回滚完整。
- [旧客户端仍调用 storage-space 路由] → 保留只读和文件兼容路由一个发布周期并标记 deprecated，但立即禁止创建新空间。
- [前端提前部署导致接口不匹配] → 后端先发布兼容响应与新路由，契约稳定后才生成和部署前端。
- [历史应用已有多个空间] → 不自动挑选，隔离写操作并输出确定性修复清单。
- [公开响应泄漏 provider 信息] → storage 摘要只返回逻辑路径、状态、用量和配额，不返回 Bucket、连接、凭据或物理 URL。

## Migration Plan

1. 增加后端审计命令和数据库约束准备，运行只读预检并保存冲突报告。
2. 实现租户默认根与应用原子初始化，补充应用只读 storage 摘要和应用上下文服务。
3. 回填无冲突历史应用；隔离冲突项；验证对象 Key、配额、授权和任务引用未改变。
4. 发布新 OpenAPI，移除创建空间操作，兼容旧文件路由并标记 deprecated。
5. 后端全量测试、迁移测试和共享 S3 集成验证通过后，更新前端生成类型。
6. 移除前端所有创建/绑定/选择空间流程，改为应用上下文和只读展示，完成端到端联调。

回滚时先回滚前端，再恢复旧后端路由；数据库新增内部记录保留且不删除对象。已隔离数据维持只读，直到修复或确认安全。
