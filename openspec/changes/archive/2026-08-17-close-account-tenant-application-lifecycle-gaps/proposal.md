## Why

账户、租户和应用目前分别拥有 `disabled`、`suspended`、`pending_takeover` 等局部状态，但没有统一的软删除状态、删除审计和父子资源失效规则。部分服务层查询只按 `tenant_id` 或资源 ID 查询，可能把已停用的成员、租户、应用、存储空间或关联数据继续返回给调用方，导致生命周期状态与授权、查询结果不一致。

## What Changes

- 为平台账户、租户和应用增加可审计的软删除生命周期，包括删除状态、删除时间、操作者和原因；删除不执行物理级联删除。
- 账户邮箱和系统号改为 PostgreSQL 部分唯一索引，仅对非删除账户保持唯一；删除账户不再阻塞身份复用，同时保留原账户历史记录。
- 定义账户、租户、应用的状态转换、恢复边界和终态规则，区分停用、暂停、待接管与删除。
- 让会话、成员关系、Principal、平台角色、API Key、存储连接、存储空间、文件会话、文件操作和授权绑定在父对象失效时立即或事务内失效。
- 统一服务层与持久层查询关联父级状态；默认业务查询排除删除或无效对象，平台审计查询可通过显式参数查看历史对象。
- 为删除、恢复、关联资源失效和跨状态查询补充 API 契约、数据库迁移、审计记录和回归测试。

## Capabilities

### New Capabilities

- `resource-lifecycle-state-management`: 账户、租户、应用及其关联资源的软删除、恢复、状态传播和关联查询闭环。

### Modified Capabilities

无。现有身份、应用和文件规格的具体行为由新生命周期能力统一补充，避免只修改单个领域而遗漏跨域关联查询。

## Impact

- 数据库模型与 Alembic 迁移：账户、租户、应用增加删除元数据；账户唯一约束改为部分唯一索引。
- 服务与仓储：平台控制面、身份授权、应用/API Key、存储、文件、配额和审计查询增加状态关联过滤。
- API：新增或补充软删除、恢复、历史查询参数和明确状态响应；默认列表和详情不返回已删除对象。
- 运行时：删除账户/租户/应用需要撤销会话、凭证和授权，文件对象的物理 S3 清理由既有异步删除流程承接。
- 测试与契约：增加状态矩阵、父级删除传播、恢复、唯一索引和跨租户/跨状态隔离测试。
